Experimental `temporalio.contrib.streams`: a Worker built from a client that carries a stream store waits, when it stops, for up to 10 seconds for the stream notifications Core still has out. `StreamStorePlugin.flush_notifications()` does the same for a process that holds only a client.
Experimental `temporalio.contrib.streams`: `StreamStorePlugin.notify_on_append()` tells each stream's notifier on the server when the stream moves while a reader sleeps on it, with `every_append=True` for readers that can't arm. `StreamHandle.close()` and `StreamStorePlugin.close_stream()` close a stream with a result or an `error=`, which reaches every reader that sleeps on the stream.
Experimental `temporalio.contrib.streams`: with `notify_on_append()` on, an idle `StreamHandle.read()` sleeps on the stream's notifier on the server instead of holding a store read open. It arms the stream after 2 seconds with no record, waits for a notification or the close, and reads again at the server's wait limit. On a server without the notifier it waits in the store as before.
Experimental `temporalio.contrib.streams`: a `StreamHandle.read()` of a topic closed with `error=` raises that error after the last record.
Experimental `temporalio.contrib.streams`: `workflow_reader()` reads a stream in Workflow code, one Local Activity per batch, with every record kind including `SUPERSEDED`. An idle reader sleeps on the stream's notifier with no Local Activity and no timer, and `position` lets the next run resume after Continue-as-New. It needs a server with the stream notifier and Workflow wake target.
Experimental `temporalio.contrib.streams`: a `workflow_reader()` ends its Workflow Task after 100 commands or 2 seconds by default (`TaskCutoff`), so a busy reader doesn't hold back the Workflow's other work. It asks Core to complete the task through the new `heartbeat_task` flag while its read runs on.
Experimental `temporalio.contrib.streams`: `close_workflow_stream(topic, result=, error=)` closes a Workflow's own stream from Workflow code. The topic's writer flushes and writes `FINISH` first, then one Local Activity closes the store and the stream's notifier, so every reader ends and sleeping readers see the outcome.
Experimental `temporalio.contrib.streams`: `StreamClosedError.closed_by` names who closed the stream. A flush that runs again after a failed Workflow Task, and finds the stream closed by its own run, takes the refusal as done.
Experimental `temporalio.contrib.streams`: `workflow_reader()` records each read's range and digest in History in place of its records by default, and replay reads the range from the store again before Workflow code sees it. `replay_from_store=False` records each batch in History instead. Other records fail the Workflow Task as nondeterministic, and a lost range fails it for a retry with `StreamReplayRangeLostError`. `RedisStreams` takes `floor_lease` and `floor_release_grace`.
