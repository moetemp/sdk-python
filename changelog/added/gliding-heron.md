Core: Experimental: a Workflow publishes stream records with `WorkflowOutputStreamCommit` in its activation completion. The Worker appends them to its `stream_store` before it reports the completion, so readers see them while the Workflow Task runs, and nothing goes to History. The producer is `@` and the run id. The attempt is the last completed task's WorkflowTaskStarted event id shifted left 16 bits, plus 1 and the task's failed or timed-out reruns since. Sequences start at 1 per attempt. Replay appends nothing. A store that refuses the append fails the Workflow Task. Once the server accepts a task, Core retires the dedupe sessions of the run's earlier attempts. The C bridge's worker options take the process's stream store as `stream_store`.
Core: Experimental: a read reports `SUPERSEDED` for a Workflow producer only when its attempt keeps the high bits (the same task) and raises the low 16 bits (a rerun). A higher prefix is the next task and reads with no supersession.
