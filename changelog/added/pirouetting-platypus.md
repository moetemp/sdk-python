Add experimental `temporalio.contrib.streams` so Activities and clients can append ordered records to a Workflow's stream in Redis, and outside readers can follow it from a cursor. The `temporalio-streams` crate runs the store and the reader rules in process, so every SDK reads the same records.
A Workflow publishes to its own stream with `stream_producer`. The Worker sends each live activation's records with `PublishWorkflowTask` before it completes the activation, so readers see them while the Workflow Task runs and nothing goes to History. If the store fails the append, the Workflow Task fails with `StreamOutputNotAppended`. A topic the store reports closed drops its records with a warning and counts `workflow_stream_output_dropped`.
A Workflow's producer attempt is `(prefix << 16) | retry`, where `prefix` is the WorkflowTaskStarted event id of the run's last completed Workflow Task and `retry` counts that task's reruns since, from 1. So a read reports `SUPERSEDED` only for a rerun of the same task. `SupersessionTracker` tells a reader which earlier records each `SUPERSEDED` withdraws.
A Local Activity publishes to its Workflow's stream with `stream_producer`, under a producer identity that survives its reruns. Its attempt comes from the facts of the Workflow Task in which Core dispatched the call, with no server call, and a reader withdraws its records when that task never completed.
A read of a Workflow that Temporal doesn't know yet answers empty for `owner_start_grace` (60 seconds unless set), so a reader can start before its owner.
A client `read()` waits `idle_wait` (2 seconds by default) in the store before it answers empty and reads again.
